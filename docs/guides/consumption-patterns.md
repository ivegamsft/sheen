# Consumption Patterns

These are the most common ways teams consume sheen.

<div class="grid cards" markdown>

-   **Solo designer**

    Want quick review helpers and a small sync surface.

    [Start with Lean mode](../getting-started/adoption-modes.md#lean-mode)

-   **Designer + engineer**

    Need tokens plus a small set of workflow helpers.

    [Use Token-only mode](../getting-started/adoption-modes.md#token-only-mode)

-   **Platform team**

    Want reproducible config, validation, and CI gates.

    [Read token build + CI](token-build-ci.md)

-   **Org rollout**

    Need a decision path for broad adoption and governance.

    [Use the catalog and support docs](../discovery/catalog.md)

</div>

## Pattern 1: solo or small team

- start with Lean mode
- keep the allow-list narrow
- validate one workflow before broadening scope

## Pattern 2: design + engineering pair

- use Token-only mode if token consistency is the first priority
- add guides for config and adoption
- fold in skills or agents only when the workflow needs them

## Pattern 3: platform or governance team

- pin a release tag
- validate tokens and docs in CI
- document the chosen sync profile so other teams can follow it

## Pattern 4: full org adoption

- keep one path for consumer onboarding
- use the catalog to separate discovery from reference
- publish support links close to the entry points
