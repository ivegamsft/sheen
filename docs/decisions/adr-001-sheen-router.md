## Context

`basecoat-sheen` shipped **v0.5.0** with 46 domain skills and 6 agents — all scoped to
UX and design — but had no router. Users had to know the exact skill name (`design-debate`,
`accessibility-audit`, etc.) to invoke one. There was no discoverable entry point,
no controlled vocabulary, and no documented multi-agent composition patterns.

The `basecoat` governance repo (vendored into sheen) provides a router skill
(`.github/skills/basecoat/`) as a reference model. Three options were evaluated for
how to build an equivalent for the sheen design domain.

## Options Considered

### Option 1 — Thin Shim: extend basecoat keywords with sheen entries
Add sheen domain keywords (`wireframe`, `token`, `brand`, `a11y`, …) to the existing
`basecoat` governance routing table. No standalone sheen router; `/basecoat` is the
only entry point.

**Weighted score: 6.6 / 10**

Rejected because basecoat categories (Development, Architecture, DevOps…) don't map
to sheen pillars (Tokens, Brand, Usability, Accessibility, IA, Governance). Sheen
concerns would bleed into the cross-domain router, and users would need to type
`/basecoat wireframe` rather than `/sheen wireframe`.

### Option 2 — Full Mirror: standalone `sheen` skill, identical structure to basecoat
Create `.github/skills/sheen/` with the identical file shape as basecoat. No integration
with basecoat's keyword table.

**Weighted score: 7.9 / 10**

Better accuracy and learnability, but two completely independent routers with no
cross-referencing. A user who knows `/basecoat` would not discover `/sheen`.

### Option 3 — Federated Delegate *(chosen)*
Create a standalone `/sheen` router (Option 2 structure) **and** register sheen as a
named delegate in basecoat's governance table, so `/basecoat ux` routes into sheen.
Additionally: a machine-readable vocabulary (`sheen.vocab.yaml`) derived at build time
from `sheen-metadata.json`, and factory composition patterns documented alongside the
router.

**Weighted score: 9.0 / 10**

## Decision Criteria

| Criterion | Weight | Opt 1 | Opt 2 | Opt 3 |
|---|---|---|---|---|
| Consistency with basecoat conventions | 30% | 10 | 9 | 9 |
| Sheen-domain accuracy | 25% | 4 | 9 | 10 |
| Learnability / discoverability | 20% | 5 | 8 | 9 |
| Maintenance cost | 15% | 9 | 5 | 7 |
| Factory / parallelism fit | 10% | 6 | 8 | 9 |
| **Weighted total** | | **6.6** | **7.9** | **9.0** |

Sensitivity check (flip top weight to sheen-domain accuracy at 35%): Option 3 = 9.2,
Option 2 = 8.0, Option 1 = 5.3. Decision unchanged.

## Decision

**Adopt Option 3 — Federated Delegate.**

Build four layers:

1. **Router skill** — `.github/skills/sheen/` with `SKILL.md`, `eval.yaml`,
   `references/authoring.md`, `references/governance.md`. Six pillar-keyed columns
   (Tokens, Brand, Usability, Accessibility, IA, Governance) with keyword-to-agent table.

2. **Intent vocabulary** — `sheen.vocab.yaml` at repo root, generated by
   `scripts/build-metadata.ps1` from the skill/agent inventory. 46 intents each with
   `keywords[]`, canonical `skill`, and canonical `agent`. Validated by `--Check` mode
   and the `catalog-drift` CI gate.

3. **Pillar routing** — 6 pillars × 4–8 keywords each → one canonical agent per pillar.

4. **Factory patterns** — `references/factory-patterns.md` documents three multi-agent
   composition patterns: Parallel Audit, Serial Decision-Chain, Token Cascade.

## Consequences

- **Positive:** `/sheen` works standalone; `/basecoat ux` also lands users here once
  the basecoat delegate entry PR is raised.
- **Positive:** `sheen.vocab.yaml` is machine-generated — keyword table never drifts
  from the inventory.
- **Positive:** Factory patterns give fleet-agent operators concrete prompt templates.
- **Risk:** Basecoat delegate entry requires an upstream cross-repo PR.
  Until that lands, `/basecoat ux` falls through to basecoat's own `@ux-designer` (narrower
  scope). Tracked as a follow-up issue.
- **Risk:** Maintenance of the `$intents` table in `build-metadata.ps1` is manual; a
  new skill that isn't registered there won't appear in `sheen.vocab.yaml`.
