# .lexicon.md — basecoat-sheen

> Canonical vocabulary, taxonomy, and brand voice for the basecoat-sheen repository.
> Mirrors basecoat's `.lexicon.md`; sheen adds the design/token vocabulary. Run the
> `lexicon` skill in audit mode to detect drift once it lands.

---

## 1. Vocabulary Registry

| Canonical term | Definition | Do not use | Notes |
|---|---|---|---|
| **sheen** | The product/finish-coat name in prose and headings | Sheen (mid-sentence), base-coat-sheen | Lowercase; the "finish coat" on basecoat |
| **basecoat-sheen** | The repository identifier in code, URLs, and file paths | basecoat_sheen, sheen-repo | All lowercase, hyphenated |
| **basecoat** | The upstream engineering-SDLC framework sheen builds on | Base Coat, BaseCoat | Vendored read-only under `vendor/basecoat/` |
| **finish coat** | The metaphor for sheen's role: the design/UX layer over basecoat's engineering base | top coat, overlay (ambiguous) | Prose metaphor only |
| **token** | A DTCG/W3C design token (`$type`/`$value`/`$description`) under `tokens/` | variable, constant, setting | Singular: token; plural: tokens |
| **core token** | A raw global primitive (palette ramp, type scale, spacing, radius, elevation, material, motion) | base token, raw var | The `tokens/core/` tier |
| **semantic token** | An alias/role token referencing core (e.g. `color.surface`, state tokens) | themed token, mapped token | The `tokens/semantic/` tier |
| **theme** | A light / dark / high-contrast / brand override of semantic tokens | mode (ambiguous), skin | The `tokens/themes/` tier |
| **pillar** | A catalog grouping for assets (foundations, brand, IA, usability, a11y, content, security, mapping, lifecycle, governance) | category (ambiguous), band | Used in skill/agent metadata |
| **band** | An instruction layer number (10 core … 90 standards) | tier (token-only), level | Instruction-file numbering only |
| **agent** | A `*.agent.md` file defining an autonomous Copilot role | bot, assistant, module | Singular: agent; plural: agents |
| **skill** | A `SKILL.md` in `skills/<name>/` with reference knowledge/templates/tools | plugin, extension, library | Singular: skill; plural: skills |
| **instruction** | A `*.instructions.md` file loaded as ambient context | rule, guideline, policy | Named `sheen-<NN>-<layer>-<topic>` |
| **asset** | Any skill, agent, instruction, prompt, or token set | resource, artifact, component | Collective noun |
| **consumer** | A repository that runs `sync.*` to adopt sheen assets | user, client, adopter | The repo that uses sheen |
| **sync** | Running `sync.ps1` / `sync.sh` to overlay sheen assets into a consumer | install, deploy, import | The act of adopting/refreshing |
| **manifest** | The record `sync.*` writes of what it placed, so `rollback.*` can revert | log, receipt (informal) | JSON; consumed by rollback |
| **drift** | When the catalog, `sheen-metadata.json`, and specs disagree, or a consumer lags upstream | lag, stale (informal) | Catalog drift and version drift |

## 2. Naming & precedence

- sheen assets use the `sheen-*` prefix; basecoat assets keep `basecoat-*`. The two
  namespaces **never collide**, so both sync into a consumer together.
- Asset names are **kebab-case** and **stable once published** — a rename is a
  breaking change (major version bump + CHANGELOG migration note).
- Where a design concern overlaps an engineering one, the sheen asset governs the
  design surface and delegates deeper engineering/security work to the vendored
  basecoat asset.

## 3. Voice

Clear, calm, and specific. Prefer plain language (ISO 24495-1) and the design values
in [`docs/design-context.md`](docs/design-context.md). Describe what an asset *does*
and when to use it; avoid hype and undefined jargon (add new terms here first).
