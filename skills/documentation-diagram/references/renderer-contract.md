# Static Diagram Renderer Contract (#113; epic #110, Position C)

Read before rendering: the type/schema table, redirects, accessibility/lint
requirements, scenarios, and output schema are operative, not optional examples.

## Scope (ADR-006)

**16 included types** — `render-diagram.ps1 -Type <name>`:

| Type flag | Diagram | Spec shape (top-level fields) |
|---|---|---|
| `bar` | Bar chart | `title`, `categories: [{label, value}]` |
| `line` | Line chart | `title`, `series: [{name, points: [{x,y}]}]` |
| `sankey` | Sankey diagram | `title`, `nodes: [{id,label,column}]`, `links: [{source,target,value}]` |
| `treemap` | Treemap | `title`, `items: [{label, value}]` |
| `gantt` | Gantt chart | `title`, `tasks: [{label, start, duration}]` |
| `kanban` | Kanban board | `title`, `columns: [{label, cards: [string]}]` |
| `story-map` | Story map | `title`, `activities: [string]`, `releases: [{label, storiesByActivity: [[string]]}]` |
| `user-journey` | User journey map | `title`, `stages: [{label, action, emotion: 1-5}]` |
| `quadrant` | Quadrant chart | `title`, `xAxis`, `yAxis`, `items: [{label, x: 0-1, y: 0-1}]` |
| `fishbone` | Fishbone (cause-and-effect) | `title`, `effect`, `categories: [{label, causes: [string]}]` |
| `funnel` | Pyramid / funnel | `title`, `levels: [{label, value}]` |
| `org-chart` | Org chart | `title`, `root: {label, children: [...]}` |
| `loop` | Loop / flywheel | `title`, `steps: [string]` |
| `timeline` | Timeline | `title`, `events: [{label, date}]` |
| `venn` | Venn diagram (2 or 3 sets) | `title`, `sets: [{label}]`, `overlapLabel?` |
| `security-matrix` | DP security control matrix | `title`, `rows: [string]`, `cols: [string]`, `cells: [[0-3]]` |

Runnable sample specs for every type are in [../samples/](../samples/).
The source-checkout path used in commands is `skills/documentation-diagram/samples/*.json`.

**Excluded types** (route out with a clear message — ask for these and the renderer will refuse and redirect):

| Type | Why excluded | Where to go instead |
|---|---|---|
| Scatter | Statistical/reporting chart, not a documentation diagram | `skills/data-visualisation` |
| Polar / Radar | Statistical/reporting chart | `skills/data-visualisation` |
| Wardley map | No stable open-source layout algorithm to adapt without forking a second style system | Not supported |
| Live/reporting dashboard | Out of scope — this skill renders static docs artifacts, not live data | `skills/data-visualisation` |

## Usage

Run commands from a sheen source checkout, not the synced skill folder. Source
tools: [renderer](https://github.com/ivegamsft/sheen/blob/main/scripts/render-diagram.ps1),
[skin builder](https://github.com/ivegamsft/sheen/blob/main/scripts/build-diagram-skins.ps1),
[icon builder](https://github.com/ivegamsft/sheen/blob/main/scripts/build-icons.ps1),
[geometry lint](https://github.com/ivegamsft/sheen/blob/main/scripts/lint-diagram-geometry.ps1),
and [slop audit](https://github.com/ivegamsft/sheen/blob/main/scripts/audit-diagram-slop.ps1).
These scripts and their generated `dist/` outputs are not bundled here.

```
pwsh scripts/render-diagram.ps1 -Type <type> -SpecPath <spec.json> \
     -OutPath <out.html> [-Theme light|dark|high-contrast]
```

Requires `dist/diagram-skins/<theme>.json` (`scripts/build-diagram-skins.ps1`, #116) and `dist/icons/manifest.json` (`scripts/build-icons.ps1`, #111) to exist — both are `dist/` build outputs regenerated by the `tokens` CI job, never hand-edited.

Output is a **self-contained HTML file**: no runtime dependencies, no Mermaid, no CDN fonts, static by default (ADR-003 — no `<animate>`, no CSS transition). Every colour is read from the active diagram skin (ADR-005) — never a hand-picked hex.

## Sample Prompts

### Render a diagram from a spec

```
@documentation-diagram render an org chart for the platform engineering
team from skills/documentation-diagram/samples/org-chart.json using the
dark theme
```

### Pick the right type for a documentation need

```
@documentation-diagram I need to document our deployment pipeline stages
and rollback path in the runbook — what diagram type should I use?
```

**Output:** recommends `timeline` or `loop` (if pipeline is cyclic), with the spec schema and a link to the matching sample.

### Excluded-type redirect

```
@documentation-diagram render a scatter plot of latency vs. load
```

**Output:** refuses with a clear message: "`scatter` is out of scope for documentation-diagram (ADR-006) — use `skills/data-visualisation` for statistical/reporting charts instead."

## Accessibility Contract

Every rendered diagram (matching `skills/data-visualisation`'s established contract):

1. `role="img"` on the SVG root, with a `<title>` and `<desc>` derived from the spec
2. A visually-hidden `<table>` data fallback per WCAG 1.3.1
3. No colour-only encoding — the DP security matrix, for example, pairs opacity with a numeric risk label and an icon, never colour alone
4. Static by default — no motion to reduce, so no `prefers-reduced-motion` fallback is needed (ADR-003)

## Design and Lint Contract

Rendered SVG must pass, unmodified:

- `scripts/lint-diagram-geometry.ps1` (#118) — connector SLANT (0/45/90° only), SHARED-ATTACH, OVERLAP-PATH, LABEL-UNMASKED, CLIPPED-LABEL, TRANSIT-BEHIND, DENSITY (≤9 `id`-bearing structural nodes)
- `scripts/audit-diagram-slop.ps1` (#115) — STRAY-HEX (skin roles only), ACCENT-BUDGET (≤2 focal-emphasis elements), RADIUS (≤10px), SHADOW (none), MONO-FONT (none)

All 16 sample specs are validated against both scripts in CI (`tokens` job) on every change to `scripts/render-diagram*.ps1`.

## Output Schema

```yaml
discriminator: rendered-diagram
type: string              # one of the 16 included types
theme: light | dark | high-contrast
out_path: string
width: number
height: number
geometry_lint_pass: boolean

```
